## 方向一：职业教练系统（Phase 2）

### 2.1 数据模型扩展 ⚠️ **最优先**

**现状**：只有 who/have/want/gap/plan 五个 section，没有任务和打卡概念

**需求**：
- 新增 `Task` 模型（id, name, deadline, status, priority）
- 新增 `CheckIn` 模型（task_id, timestamp, status, notes）
- 新增 `Adjustment` 模型（trigger, trigger_type, changes）
- 更新 `CareerProfile`，添加 checkins 和 adjustments 字段

**优先级**：P0 | **工作量**：中

---

### 2.2 任务管理模块 ⚠️ **最优先**

**现状**：没有任务管理功能

**需求**：
- `task_manager.py`：任务创建、打卡、调整
- 支持从路线图自动生成任务
- 支持任务状态更新（pending → in_progress → completed）
- 支持超期检测和自动压缩

**优先级**：P0 | **工作量**：大

---

### 2.3 洞察引擎 ⚠️ **最优先**

**现状**：没有主动洞察功能

**需求**：
- `insight.py`：洞察检查、调整建议
- 三种触发方式：
  - 阶段审计：完成阶段后自动触发
  - 事件触发：用户报告事件时触发
  - 主动检查：每次对话自动检查
- 运行时指令注入到 system prompt

**优先级**：P0 | **工作量**：大

---

### 2.4 静态前端 ⚠️ **优先**

**现状**：没有可视化界面

**需求**：
- `dashboard.html`：进度仪表盘
- 读取 `progress.json` 显示进度
- 支持任务勾选打卡
- 总体进度条、当前阶段详情、今日任务列表

**优先级**：P1 | **工作量**：中

---

### 2.5 MCP Tools 集成 ⚠️ **优先**

**现状**：没有任务和洞察相关工具

**需求**：
- `get_today_tasks`：获取今日任务
- `checkin_task`：打卡任务
- `get_progress`：获取进度
- `trigger_insight`：触发洞察
- `suggest_adjustment`：提出调整建议
- `apply_adjustment`：应用调整

**优先级**：P1 | **工作量**：中

---

### 2.6 调整策略 ⚠️ **优先**

**现状**：没有自动调整功能

**需求**：
- 小幅调整（自动）：超期 1-2 天，压缩后续任务各 0.5 天

**优先级**：P1 | **工作量**：中

## 方向二：LLM Prompt 和工作流调优

### 1.1 Prompt 模板变量替换脆弱 ⚠️

**现状**：`sop_executor.py:63-71` 使用 `.format()` 替换，缺失变量会报错

**问题**：模板引用了前序步骤未生成的变量时，只能跳过或用原始模板

**建议**：
- 实现**安全模板引擎**：支持默认值 `{persona.target_role:未知}`
- 支持**条件渲染**：`{% if persona %}...{% endif%}`

**优先级**：P1 | **工作量**：中

---

### 1.2 输出格式解析不稳定 ⚠️

**现状**：`gap_analyzer.py:280-313` 用正则从 markdown code block 提取 JSON

**问题**：LLM 输出格式不稳定，解析失败时只能返回 raw 文本

**建议**：
- 在 prompt 中强化**输出格式约束**
- 实现**多策略解析**：先尝试 JSON，再尝试正则提取关键字段
- 添加**重试机制**：解析失败时让 LLM 重新格式化

**优先级**：P0 | **工作量**：中

---

### 1.3 SOP 步骤间上下文传递不完整 ⚠️

**现状**：`sop_executor.py:150-154` 将检索结果注入 context，但只取前 500 字符

**问题**：信息截断可能导致关键数据丢失

**建议**：
- 实现**智能摘要**：用 LLM 提取关键信息，而非简单截断
- 支持**结构化传递**：传递完整结构化数据，让 LLM 按需使用

**优先级**：P1 | **工作量**：中

---

### 1.4 缺少工作流分支和循环 ⚠️

**现状**：SOP 是线性执行的，不支持条件分支和循环

**问题**：无法根据中间结果调整后续步骤

**建议**：
- 支持**条件分支**：`if persona.experience_level == "应届" then ...`
- 支持**循环**：`for each skill_gap ...`
- 实现**动态 SOP**：根据用户画像选择不同的 SOP 路径

**优先级**：P2 | **工作量**：大

---

### 1.5 缺少 Prompt 版本管理 ⚠️

**现状**：Prompt 模板硬编码在 YAML 文件中，无法版本控制

**问题**：优化 prompt 时无法回滚，无法 A/B 测试

**建议**：
- 支持**多版本 prompt**：`resume_screening_v1.yaml`、`resume_screening_v2.yaml`
- 实现**prompt 模板继承**：基础模板 + 公司定制模板
- 添加**prompt 性能追踪**：记录哪个版本的分析更准确

**优先级**：P2 | **工作量**：中
